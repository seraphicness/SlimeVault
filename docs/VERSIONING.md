# 버전 관리

## 소스와 릴리스

- SlimeVault 제품 버전은 루트 `VERSION`에서 관리합니다. 현재 `0.2.0-dev`입니다.
- Cargo 내부 crate 버전은 기반 Garage의 `2.5.0`을 유지합니다. 내부 버전을 제품 릴리스 번호로 해석하지 않습니다.
- SlimeVault 릴리스 태그는 `slimevault-v0.2.0` 형태를 사용합니다. 아직 릴리스 태그를 만들거나 배포하지 않았습니다.
- `Cargo.lock`을 커밋하고 CI·릴리스 빌드는 `--locked`로 실행합니다.
- API와 저장 형식의 호환성 변경은 CHANGELOG에 기록합니다. 개발 중인 0.x에서 호환되지 않는 변경은 minor 버전으로 구분합니다.
- 원본 Garage 이력은 보존합니다. upstream 갱신은 별도 브랜치에서 병합하고 월드 이력·삭제·복원 회귀 테스트를 통과한 뒤 통합합니다.

## 월드 리비전

`.slime` 키는 완료된 리비전과 삭제 마커를 보존합니다. 다른 key의 기존 Garage 데이터 모델은 유지합니다. 이 보존 규칙은 CRDT 병합에서 키로 결정하므로 모든 노드가 동일한 SlimeVault 빌드여야 합니다. 원본 Garage 노드와 혼합 클러스터를 운영하면 안 됩니다.

새로운 저장 형식 마커를 도입하지 않았지만 동작은 upstream과 다릅니다. 원본 Garage로 되돌리면 과거 이력이 정리될 수 있으므로 데이터 백업 없이 다운그레이드하지 않습니다.

`slime_world_only = false`는 기존 범용 S3 테스트·마이그레이션을 위한 쓰기 정책 해제 옵션입니다. 이 옵션을 꺼도 `.slime`의 이력 보존 규칙은 유지됩니다.

0.2부터 owner 제어 API의 과거 리비전 정리와 보존 정책을 제공합니다. 단조 증가 Aborted 상태와 기존 블록 참조 카운트·지연 GC를 사용합니다. 최신 리비전·보호 사본은 직접 정리할 수 없습니다.

0.2의 임대·보호·보존 상태는 조정 노드의 `slimevault_world_control_v1` metadata tree에 저장합니다. 상태 인코딩은 MessagePack입니다. 다른 노드로의 자동 복제·조정 노드 자동 장애 전환은 없습니다. 조정 노드 metadata와 node ID를 함께 백업해야 합니다.

0.1에서 업그레이드하면 전용 쓰기 경로의 임대와 SRF 13 구조 검사가 기본 활성화됩니다. 기존 연동 클라이언트는 임대 token 헤더를 추가해야 합니다. 모든 노드를 같은 빌드로 전환하고 `world_coordinator`를 동일하게 설정합니다. 쓰기 경로를 완화하는 호환 옵션은 문서화한 목적에 한해 명시적으로 설정합니다.
